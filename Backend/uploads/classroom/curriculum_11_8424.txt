# Lesson Plan – React JS  
**Subject:** Front‑End Development  
**Topic:** React JS (Fundamentals & Core Practices)  
**Class Length:** 60 minutes  
**Audience:** Upper‑level undergraduate students (third‑year) who have basic HTML, CSS, and JavaScript knowledge.  

---  

## 1. Learning Objectives  

By the end of the session, students will be able to:  

1. **Explain** the motivation behind React and the problems it solves in modern UI development.  
2. **Identify** and **describe** the core concepts of React: components, JSX, props, state, lifecycle, hooks, and the virtual DOM.  
3. **Create** a simple functional component using JSX, pass data via props, and manage local state with the `useState` hook.  
4. **Demonstrate** how to fetch data from an API inside a component using the `useEffect` hook.  
5. **Critically discuss** the trade‑offs of using React versus alternative frameworks (Vue, Angular, Svelte).

## 3. Core Concepts Explanation  

### 3.1 Components  
- **Definition:** Reusable, self‑contained pieces of UI that return a description of what should appear on the screen.  
- **Types:**  
  - *Functional components* – plain JavaScript functions that return JSX. Preferred for new code.  
  - *Class components* – ES6 classes extending `React.Component`. Still valid but largely superseded by hooks.  

### 3.2 JSX (JavaScript XML)  
- **What it is:** A syntax extension that looks like HTML but is compiled to `React.createElement` calls.  
- **Key rules:**  
  - Must have a single root element.  
  - Use `className` instead of `class`.  
  - JavaScript expressions are embedded with curly braces `{}`.  

### 3.3 Props (Properties)  
- **Read‑only** values passed from a parent component to a child.  
- Enable component composition and data flow “top‑down”.  

### 3.4 State  
- **Mutable** data that lives inside a component and triggers a re‑render when changed.  
- In functional components, state is created with the `useState` hook:  

```js
const [count, setCount] = useState(0);
```

- Updating state is asynchronous; React batches multiple updates for performance.  

### 3.5 Virtual DOM & Reconciliation  
- React keeps an in‑memory representation of the UI (the virtual DOM).  
- When state or props change, React creates a new virtual tree, diffs it against the previous tree, and applies only the minimal set of real DOM changes.  
- This approach yields fast UI updates and abstracts away manual DOM manipulation.  

### 3.6 Hooks (Functional‑Component Lifecycle)  
| Hook | Purpose | Typical Use |
|------|---------|-------------|
| `useState` | Declare local state | Counter, form fields |
| `useEffect` | Run side effects (data fetch, subscriptions) | API calls, timers |
| `useContext` | Consume a React context | Theme, auth |
| `useReducer` | Complex state logic similar to Redux | Form wizard, game state |
| `useMemo` / `useCallback` | Memoize expensive calculations or functions | Performance tuning |

**`useEffect` pattern:**  

```js
useEffect(() => {
  // side effect code
  return () => {
    // optional cleanup
  };
}, [dependency1, dependency2]); // runs when dependencies change
```

## 4. Discussion Questions  

1. **Conceptual:** *Why does React need a virtual DOM? Could we achieve the same performance by directly manipulating the real DOM?*  
2. **Practical:** *When would you prefer a class component over a functional component today?*  
3. **Design:** *How does the “single source of truth” principle manifest in React’s state management?*  
4. **Ecosystem:** *What are the advantages and disadvantages of using a large library like React compared to a lightweight alternative such as Svelte?*  
5. **Future‑Oriented:** *React is moving toward server‑side rendering (Next.js) and concurrent features. How might these impact the way we structure components today?*

## 5. In‑Class Activities  

### Activity 1 – **Props & Composition (8 min)**  
- **Goal:** Reinforce data flow from parent to child.  
- **Instructions:**  
  1. In the provided starter file, locate the `Counter` component created earlier.  
  2. Create a new component `Dashboard` that receives `count` as a prop and displays it inside a styled card.  
  3. Render `<Dashboard count={count} />` from the main `App` component.  
- **Assessment:** Walk around; verify that each pair correctly passes the prop and that the UI updates when the button is clicked.  

### Activity 2 – **Fetching Data with `useEffect` (7 min)**  
- **Goal:** Practice side‑effects and async handling.  
- **Instructions:**  
  1. Add a new component `UserList`.  
  2. Inside `UserList`, use `useEffect` to fetch the user array from the JSONPlaceholder endpoint.  
  3. Store the result in state (`users`) and render a simple unordered list of usernames.  
- **Tip for Students:** Remember to include an empty dependency array (`[]`) to run the fetch only once on mount.  

### Activity 3 – **Mini Debate (5 min)**  
- **Goal:** Develop critical thinking about framework choice.  
- **Setup:** Split the class into two groups. One argues that React is the best choice for a large‑scale enterprise app; the other argues for an alternative (Vue, Angular, or Svelte).  
- **Outcome:** Each group presents two supporting points; the instructor highlights trade‑offs (learning curve, community, tooling, performance).

## 6. Homework Assignment  

**Task:** Build a **Todo List** application using only functional components and React hooks.  

**Requirements:**  

1. **Add Todo:** Input field + button; new items appear in a list.  
2. **Toggle Completion:** Clicking a todo toggles a `completed` flag; completed items render with a line‑through style.  
3. **Persist Data:** Use `localStorage` to save the list; load it on component mount with `useEffect`.  
4. **Optional Bonus:** Implement a filter (All / Active / Completed) using a derived state or `useMemo`.  

**Submission:** Push the code to a public GitHub repository and share the link on the course LMS by next week.
