# Mentor AI — manager spec vs current demo

**Reviewed:** 6 October 2026. This compares the manager's supplied wireframe/product spec with the current repository. It is a **source-based demo assessment**; no browser or live service was run. Test student profiles and synthetic records are treated as legitimate demo fixtures, but a visible mock value or inert button is not counted as a working feature.

**Legend:** ✅ implemented in source; 🟡 partial, UI-only, or sample-backed; ❌ no corresponding workflow found. “Implemented” does not mean runtime QA has passed.

## C. Plain-language summary for the demo

**Strongest working story:** student joins a class, uploads material, asks questions across accessible documents, studies generated content, answers AI-generated MCQs, sees performance, and builds a personal roadmap. Professors can manage classes/curricula/resources and inspect class/student metrics. Admins can inspect academic analytics and manage users/departments.

**Biggest manager-spec gaps:** five-mode global UX, voice/floating bar, fully clickable proactive actions, exam-date scheduling, subjective practice and AI grading, expected-score/what-if prediction, live career/recruiter integration, and persistent admin reports. Several matching screens exist but use static values or local-only actions.

**Demo wording:** call fixed jobs, salaries, resume scores, assessment lists and admin reports **sample/demo data**. Call readiness and class analytics **academic signals**, not placement outcomes or proven exam-score predictions. See [QC report](MENTOR_AI_QC_REPORT.md) for source-level bugs and deployment concerns.
